# Короткий путь — мелкая правка кода

Только для класса «Короткий путь» из `SKILL.md`. `pilot.py`, `.pilot/`, дашборд, окно запуска и ворота
Requirements / Plan / Acceptance здесь не используются. Слово пользователя нужно один раз — на слияние.

1. **Требования.** Запиши бриф как `R-1…R-n` в описании PR. Чего нет в брифе — строкой «предложение»; в код оно
   не идёт без слова пользователя.
2. **Ветка и правка.** Ветка от основной по правилам репозитория. Читай только затронутые файлы и их прямых
   соседей. Правила репозитория (PR-only, UI-стандарт, языки UI) сильнее навыка.
3. **Проверка.** Тесты и сборка, которых требует репозиторий; тест на изменённое поведение, если в затронутой
   области тесты уже есть. Снимок экрана — один и только при видимом изменении UI.
4. **Один PR, одно ревью.** В описании PR таблица `R-n → что сделано → как проверено`. Ревью — один проход по осям
   «стандарты» и «соответствие `R-n`» навыком роли `review`, если он есть; без субагентов. Замечания исправь в том
   же PR.
5. **Слияние** — только по слову пользователя. В сообщении: ссылка на PR, таблица `R-n`, что не проверено.
6. **След.** После слияния — одна строка в журнале изменений, который ведёт репозиторий; ветку удалить. Если
   правила репозитория требуют проверки после выката — одна проверка затронутого сценария, итог одной строкой.

## Стоп-условия

Остановись, скажи пользователю причину одной строкой и перейди на полный пилот, если по ходу выяснилось, что:

- нужна миграция, правка схемы БД, прав доступа, политик или ролей;
- меняется серверная функция, авторизация или секреты;
- затронуто больше одного раздела или требований стало больше пяти;
- ревью нашло замечание вне затронутых файлов.
